## Overview

On eight H20-3e GPUs (four for prefill, four for decode), the final configuration lowered mean end-to-end latency from **13.63 s to 4.71 s** and nearly tripled both input and output token throughput. Prefill context parallelism with decode data parallelism gave the largest gain, followed by FP8 DeepGEMM scoring.

## Measurement Setup

The router sends each request through prefill and decode. The workers transfer the KV state directly over intra-node Mooncake NVLink. The baseline runs TP4 attention and EP4 MoE on both workers with eager BF16 Torch prefill scoring. Every run uses the same DeepSeek-V4.1-Flash checkpoint, Humming MoE backend (w4a8), DSpark block size 5, 8192-token prefill chunks.

| Workload | Value |
| --- | --- |
| Requests and concurrency | 256 requests, 24 in flight |
| Nominal input | 61,440 shared tokens + 4,096 request-specific tokens |
| Output | 500 tokens per request |
| Cache protocol | 10 warmup requests, then a cache flush before measurement |
| Observed cache hit rate | 93.21% |

Each comparison adds one change to the preceding configuration. Each result comes from a single run with all 256 requests and 128,000 output tokens completed.

## 1. Prefill CP and Decode DP

Prefill handles many token rows from a single long request. Interleaved context parallelism assigns those rows to different ranks so the four GPUs can work on the same request. Decode has many active requests with a small number of query rows each. Data-parallel attention and a data-parallel LM head assign independent requests to different ranks.

**Serving result.** Mean E2E went from **13,633.80 to 7,547.46 ms (−44.64%)**. Output throughput rose from **846.76 to 1,537.90 tokens/s (+81.62%)**.

## 2. FP8 DeepGEMM for the Prefill Indexer

The Indexer scores visible keys before selecting a small subset for attention. On Hopper, we gather each request's packed FP4 keys once, convert the queries and keys to E4M3, and call DeepGEMM's `fp8_mqa_logits` for every prefill Indexer layer. The scorer masks positions beyond each query's causal boundary, and candidate consumers keep their original candidate set.

The gather applies each FP4 block's UE8M0 scale in FP32. Before casting to E4M3, it clamps the scaled values to the format's finite range, **−448 to +448**. DeepGEMM receives unit key scales because the block scales have already been applied. Values outside the range saturate at the boundary.

![Torch scores in BF16; DeepGEMM scores in E4M3 after scaling and clamping the FP4 keys](/images/blog/deepseek-v41-h20/fp8-indexer.svg)

**Serving result.** Mean E2E went from **7,547.46 to 5,294.89 ms (−29.85%)**. Output throughput rose from **1,537.90 to 2,200.82 tokens/s (+43.11%)**. [SGLang PR #49066](https://github.com/sgl-project/sglang/pull/49066)

## 3. Breakable CUDA Graphs for Prefill

Long prefill runs launch many small kernels. Breakable CUDA Graphs capture the graph-safe stretches and replay them together, while operations that need live metadata stay eager. Bounded SWA replay captures separate buckets for the shorter decoder tail, avoiding work on the full prefill chunk in later layers.

In earlier DeepSeek-V4 experiments, the C4 Indexer padded its score buffer to the model's full context limit during graph capture. Capping the graph context with `--cuda-graph-prefill-max-context` cut capture memory from **43 GB to 18 GB** in that earlier test, which used a 16,384-token capture size. Requests beyond the cap run eagerly. The change was merged in [SGLang PR #36534](https://github.com/sgl-project/sglang/pull/36534).

**Serving result.** Mean E2E went from **5,294.89 to 5,100.87 ms (−3.66%)**. Output throughput rose from **2,200.82 to 2,290.05 tokens/s (+4.05%)**.

## 4. Tensor-Parallel MoE

Expert parallelism assigns different experts to different ranks. When routing favors a few experts, their ranks do more work and the other ranks wait at the collective. Tensor-parallel MoE shards every expert across all four ranks. Each rank shares the work for every selected expert, eliminating the imbalance workload from uneven expert routing.

**Serving result.** Mean E2E went from **5,100.87 to 4,902.85 ms (−3.88%)**. Output throughput rose from **2,290.05 to 2,380.37 tokens/s (+3.94%)**.

## 5. Larger Indexer Score Tiles

The Indexer limits the size of its temporary score matrix. At long context lengths, a small budget fits few queries, so scoring and selection repeat across many tiles. Increasing the prefill budget from **64 MiB to 2 GiB** lets each tile cover more queries.

**Serving result.** Mean E2E went from **4,902.85 to 4,827.67 ms (−1.53%)**. Output throughput rose from **2,380.37 to 2,426.16 tokens/s (+1.92%)**. [SGLang PR #49067](https://github.com/sgl-project/sglang/pull/49067)

## 6. Fuse Prefill Selection and Writeback

The Indexer needs both candidate block IDs for later layers and physical KV slots for attention. Triton combines block reduction and selection so the publisher does less intermediate work. A separate fused writeback filters invalid picks, sorts the remaining positions, and translates them to KV slots in one launch.

![Separate tensor operations become one Triton launch each for candidate publishing and KV-slot writeback](/images/blog/deepseek-v41-h20/selection-fusion.svg)

**Serving result.** Mean E2E went from **4,827.67 to 4,760.91 ms (−1.38%)**. Output throughput rose from **2,426.16 to 2,464.74 tokens/s (+1.59%)**. [SGLang PR #49069](https://github.com/sgl-project/sglang/pull/49069)

## 7. Reuse Paged Indexer K Tiles During Verification

DSpark verifies several query rows from the same request in one forward pass. Those rows look at nearly the same keys. The paged scorer loads and dequantizes one FP4 K tile into BF16, then reuses it for the request's query rows. Each row still applies its own causal limit.

![Verify queries switch from one load and dequantization each to one shared BF16 key tile](/images/blog/deepseek-v41-h20/verify-reuse.svg)

**Serving result.** Mean E2E went from **4,760.91 to 4,705.99 ms (−1.15%)**. Output throughput rose from **2,464.74 to 2,480.23 tokens/s (+0.63%)**. [SGLang PR #49068](https://github.com/sgl-project/sglang/pull/49068)

## 8. One more OPT on colocate serving

We also ran optimization experiments on a single colocated worker with four H20s. Against the TP4 baseline with DSpark, mean E2E fell from **12,563.99 to 7,957.13 ms (−36.67%)**, and output throughput rose from **947.11 to 1,482.72 tokens/s (+56.55%)**.

Beyond the PD optimizations above, we added batch-wise prefill CP and decode DP to the same worker. Prefill still splits prompt tokens across four ranks. During decode and target verification, each rank instead handles a slice of the query rows with all attention heads, and the worker gathers the results back into batch order.

![Both colocated configurations split prefill tokens; decode switches from splitting heads to splitting query rows](/images/blog/deepseek-v41-h20/colocated-cp-dp.svg)

Adding decode DP to the prefill CP configuration reduced mean E2E from **8,632.46 to 7,957.13 ms (−7.82%)** and raised output throughput from **1,377.49 to 1,482.72 tokens/s (+7.64%)**. [SGLang PR #45729](https://github.com/sgl-project/sglang/pull/45729)

## Reproduction

Install the experiment revision `91afc4f363cc60ca0bf98d38e87cc6cfa32062fe` and its matching DeepGEMM, Humming, Mooncake, and SGLang Router dependencies. The commands use the [DeepSeek-V4.1-Flash checkpoint](https://huggingface.co/deepseek-ai/DeepSeek-V4.1-Flash); you can use the same checkpoint from a local path. Start one prefill and one decode command for the configuration you want to measure, in separate terminals on the same host.

### Baseline prefill

```bash
SGLANG_ENABLE_DSV41_ENGRAM_HOST_TABLE=1 SGLANG_DSV41_ENGRAM_HOST_TABLE_LAYOUT=per_rank \
SGLANG_HUMMING_INPUT_QUANT_CONFIG='{"dtype":"float8e4m3"}' SGLANG_USE_CUDA_IPC_TRANSPORT=1 \
SGLANG_MM_FEATURE_CACHE_MB=512 SGLANG_VLM_CACHE_SIZE_MB=512 \
SGLANG_DSV41_SM90_PREFILL_INDEXER=deepgemm SGLANG_DSV41_TORCH_PREFILL_INDEXER=1 \
SGLANG_OPT_DSV41_DECODE_INDEXER_FP8=0 SGLANG_OPT_DSV41_VERIFY_INDEXER_K_REUSE=0 \
SGLANG_OPT_DSV41_VERIFY_INDEXER_BF16_K_REUSE=0 SGLANG_OPT_DSV41_TRITON_PREFILL_SELECTION=0 \
SGLANG_OPT_DSV41_LARGE_INDEXER_SCORE_BUDGET=0 SGLANG_OPT_DSV41_LARGE_PREFILL_SCORE_BUDGET=0 \
SGLANG_HOST_IP=127.0.0.1 SGLANG_MOONCAKE_CUSTOM_MEM_POOL=INTRA_NODE_NVLINK \
MC_INTRA_NVLINK=true MC_INTRANODE_NVLINK=true \
SGLANG_DISAGGREGATION_ALL_CP_RANKS_TRANSFER=1 SGLANG_OPT_MOONCAKE_NVLINK_LAYER_BATCH=0 \
SGLANG_SET_CPU_AFFINITY=1 SGLANG_JIT_DEEPGEMM_FAST_WARMUP=1 \
CUDA_VISIBLE_DEVICES=0,1,2,3 \
sglang serve --model-path deepseek-ai/DeepSeek-V4.1-Flash \
  --served-model-name llm --trust-remote-code --host 127.0.0.1 --attention-backend dsv4 \
  --moe-runner-backend humming --mm-feature-transport cuda_ipc --reasoning-parser auto \
  --tool-call-parser auto --speculative-algorithm DSPARK --speculative-dspark-block-size 5 \
  --enable-cache-report --enable-metrics --enable-strict-thinking --random-seed 42 --tp 4 \
  --disable-prefill-cuda-graph --enable-hierarchical-cache --hicache-ratio 0.25 \
  --hicache-io-backend kernel --hicache-write-policy write_through --tokenizer-worker-num 8 \
  --detokenizer-worker-num 8 --language-model-only --ep-size 4 --moe-a2a-backend none \
  --chunked-prefill-size 8192 --max-prefill-tokens 8192 --enable-decoder-swa-bounded-replay \
  --swa-full-tokens-ratio 0.1 --mem-fraction-static 0.8 --disaggregation-mode prefill \
  --disaggregation-transfer-backend mooncake --disaggregation-bootstrap-port 8998 --port 9091
```

### Router

Start the router after both workers are healthy. Run the benchmark when the router reports readiness.

```bash
python3 -m sglang_router.launch_router --pd-disaggregation \
  --prefill http://127.0.0.1:9091 8998 --decode http://127.0.0.1:9092 \
  --host 127.0.0.1 --port 9090 --worker-startup-timeout-secs 3600 \
  --disable-circuit-breaker --prefill-policy round_robin --decode-policy round_robin
```
